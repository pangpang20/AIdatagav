# 登录核对案例与反例

这是2026-10-26在数据中台项目中核对AUTH-001形成的示例，帮助理解编写尺度，不是其他应用的默认协议。具体实现来自当时的静态文件与历史截图；未取得真实认证Network或完整后端工程，功能与非功能应用验收均未执行。使用到其具体规则时应重新核对当前版本。

## 由空泛模板改为具体规格

| 先前问题 | 合格做法 |
|---|---|
| 字段表只有一行空白 | 列出账号、密码，以及受初始化结果控制的验证码和协议勾选；逐项核对名称/类型/必填/默认/边界/提示 |
| 把登录写成读取/查询、分页和列表 | 写身份认证、密码加密、会话建立、成功路由及错误恢复 |
| 只写“输入框更新草稿” | 查focus/blur、trim、加密来源、Enter与点击、条件依赖、失败后保留什么及重复请求锁 |
| 参数/URL全写待验证 | 沿API包装器、运行配置、公共客户端查到方法、相对路径、四个参数和202错误分支 |
| 布局只说“以截图为准” | 说明左侧蓝色主题插画、右侧中部白色卡片、标题、字段/按钮次序、条件行及错误/加载/窄屏 |
| 正文到处是调研标签 | 目标正文直接写业务规则；核查记录单独登记来源、实现差异、外部依赖与未执行状态 |
| 只写“高性能、安全可靠” | 质量项编号、测量环境/样本/起止点、指标及失败条件，注明是交付目标而非实测 |

## 当时查明的字段与API链

- 账号模型username，提交参数account，maxlength=20，提交trim。原非空工具不trim，因此目标规格补充trim后非空；不能把补缺口写成原实现已正确。
- 密码模型password，前端下限4字符、不trim；认证参数password为RSA-OAEP、SHA-256/MGF1 SHA-256加密后Base64。此下限只说明登录前端，不推断新增用户或服务端密码策略。
- authCode映射imgCode，图片非空才显示；协议agreeToPrivacyStatement为boolean，初始false、条件必选。无证据长度属性保留空白，不能自行填验证码位数。
- 六接口：GET `/back/common/auth/login/key`、POST `/back/common/auth/login`、GET `/back/common/user/pub/login`、GET `/back/common/captcha/captcha/img64`、GET `/back/common/user/privacy/getPrivacyStatus`、GET `/back/common/user/privacy/getPrivacy`。前缀来自当时配置，不是通用路径。
- 认证请求只有account、password、imgCode、agreeToPrivacyStatement；条件imgCode回退常量是客户端实现细节，不证明服务端可被绕过。不得为“完整”添加角色/部门/租户参数。
- 公共客户端POST JSON；HTTP 202进入业务错误处理，其他Axios接受的正常状态返回data；没有统一code=0成功判断。1109跳修改密码，1002处理失效认证，1003无权限，1012刷新。真实成功body仍需后端/隔离联调证据。
- 超时先取路径规则非负值，否则number类型请求timeout，再无数值才回退20000ms；0没有被该片段排除，所以不能声称当前请求一定20秒结束。

## 密码安全与实现差异

密码框默认遮蔽、失焦替换DOM值，不能保证用户F12读不到输入期间/组件模型/加密断点中的原值。分别写遮蔽、加密请求、TLS、服务端哈希、日志/存储边界；加密失败禁止明文回退。

公钥未被纳入原表单显示门槛、同步加密异常不一定由请求catch处理、loading按钮未必构成所有入口锁。目标规格要求公钥门控、统一try/finally、共享请求锁及离页清理；核查记录列当前代码差异，不能因正文去标签就将其报为原功能通过。

历史截图是1440×1000的单次样本；密码行有既有覆盖处理，不能当作产品填充色、真实密码值或加密结果。界面条件项未在截图显示时可用模板/代码证明其条件定义，但不能声称当时截图可见。

## 本次质量目标示例

登录制定了13项质量要求。示例目标为冷启动P95≤3秒、交互反馈P95≤100ms、指定100个并发虚拟用户下认证P95≤2秒/P99≤5秒、非预期失败率≤0.1%、月度可用率≥99.9%；还包括超时1秒内恢复、会话/限流、审计、浏览器/缩放、可访问性及资源回收。

这些数值是当时新增的开发验收目标，未进行性能压测、月度监测或安全/兼容实测。复用的是指标完整写法与来源分离，不是默认对所有模块套这组数字。
