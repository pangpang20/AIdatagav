页面字段和操作结果来自当前账号的只读取证。功能建议与页面事实分开；业务保存、删除、审批、授权及任务执行均未验收。

## 3. 编号功能需求

### GSB-500 服务目录 → 服务目录

**业务目的**：使用者在“服务目录 → 服务目录”处理对应对象；与其他菜单分别保留查询条件、对象标识和处理状态。

【页面观察】实际路径为`/gsb/catalog/list`。

**用户操作与系统响应**：

1. 从“服务目录 → 服务目录”进入目标页，先核对当前部门、空间及对象范围。
2. 页面提供的输入或选择提示为：服务中文名、服务英文名、请选择。其匹配方式、默认值和多条件组合语义待确认。
3. 列表展示：序号、编码、服务注册名称、服务中文名、服务英文名、服务提供方、调用方式、传输协议、服务类型、用途、版本、操作。记录条数、名称和当时状态属于样本。
4. 可见操作包括：关闭左侧。只有本文件另列并附目标页证据的操作才算已进入；其余仅确认入口可见。

【拟定需求】业务依赖：注册、上架、启停、消费申请、审批和IP控制的状态与权限分别确认；看到服务定义不代表可调用。

**来源与验证**：[J-GSB-001](../evidence/live-recheck-20261022/J-GSB-001.png) / [页面元素](../evidence/live-recheck-20261022/J-GSB-001.json)。仅验证已记载的页面打开和元素读取；接口、持久化、权限隔离和最终业务结果未验证。

【拟定需求】服务管理员先确定注册类型，再填写服务描述及数据契约；拟定将注册草稿、审批、上架版本和消费授权分开。提供方、数据源和资源表失效时阻止发布并保留可修复草稿。

【待确认】字段选择后参数映射、签名协议、错误响应、附件规则、版本兼容、发布前校验和调用限流需确认。

- P0：各对象的读写权限、唯一性范围、状态转换、引用保护、并发和保存结果契约。

- 删除：本轮不自动点击可能直接删除数据的入口；已有确认框证据保留于主文档，未取得确认页的对象继续待核实。

- 开发边界：可实现有依据的界面结构和标明模拟状态的原型；生产写入、接口、算法与完整状态机仍需产品及技术确认。
