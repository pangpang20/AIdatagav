# 工作空间业务需求说明

<!-- space:reviewed-spec-v1 -->
<!-- 业务规格格式:plain-v1 -->

修订日期：2026-10-28。本文定义工作空间查询、基础资料维护及配置的开发目标；规则来源、现有实现差异和受阻验收见独立核查记录。保留已发布功能、验收编号及调研档案。

## 1. 业务目标与使用角色

让获授权用户发现工作空间，维护空间基础资料、成员和资源范围，并在明确的会话上下文中使用业务应用。

- 入口：后台 → 工作空间 → 工作空间管理；完整列表路由/dop/projectSpace/index。
- 角色：空间使用者、创建者、管理员及平台授权角色。创建者与管理员是不同关系，不相互推定；角色名称、部门继承及租户边界由权限合同批准。
- 交付状态：可用于有依据的界面与前端合同适配；服务端授权、隔离、持久化、容量和生产运行尚需外部材料及隔离验收。

## 3. 功能需求

### SPACE-100 查询工作空间

**业务目的**：按空间名称和当前用户关系定位获准查看的空间，并一致展示卡片、总数和分页。

**操作与规则**：

1. 进入列表，载入允许查看的空间；按保存的有效查询上下文恢复或采用初始分页。
2. 输入名称、选择我创建的或我参与的，点击查询从第1页读取。
3. 重置清除筛选并回第1页，保留页大小；翻页读取对应范围。

**结果与异常处理**：空结果、加载失败和无权独立呈现；查询失败保留条件并可只读重试，迟到响应不能覆盖新条件。

**开发处理细则**：筛选模型初始为{}，分页默认pageNo=1、pageSize=20、order按id降序。同路径listSearchStore可恢复条件及分页，但恢复必须校验会话范围和JSON结构；不承诺跨账号恢复。查询仅更新读取状态。

### SPACE-101 查看工作空间配置

**业务目的**：按稳定空间ID查看资源、成员和部门授权状态，避免只凭列表摘要推断权限。

**操作与规则**：

1. 从获准空间的查看入口进入/dop/projectSpace/config，optType=view且携带id。
2. 读取配置、数据源候选和成员树，将关联ID映射为可识别文本。
3. 保持只读，返回来源列表时恢复当前会话有效查询上下文。

**结果与异常处理**：ID无效、对象失权、候选或详情失败显示明确状态；不能拿路由data中的旧摘要代替详情成功。只读状态不发PUT、POST保存或DELETE。

**开发处理细则**：子应用路由/projectSpace/config由壳应用挂载到/dop；query含id、JSON.stringify的data、optType。路由摘要不可信；解析错误可恢复，未获取详情前不可编辑或误示默认授权。

### SPACE-102 新增工作空间

**业务目的**：创建仅包含名称与管理员的基础空间对象，再按业务授权进入资源配置。

**操作与规则**：

1. 在允许创建且平台业务开启时打开创建工作空间抽屉。
2. 读取管理员候选，填写名称、选择稳定管理员ID并校验。
3. 明确提交后创建；只有确认业务成功并回读对象后关闭、刷新列表和顶部可选空间。

**结果与异常处理**：字段不合法定位错误；候选失败、无权或超时保留安全草稿；未知写入结果先查结果，不能重复创建或用关闭抽屉表示成功。

**开发处理细则**：每次打开创建都重置optType=add以及name、administratorId、id；使用独立草稿，防止前次编辑状态残留。提交入口共享锁；取消/右上关闭仅关闭草稿，不发创建或修改。

## 4. 字段与业务规则

- 工作空间、成员、部门、租户和资源授权分别建模；创建者createUser与管理员administratorId是两种关系。
- 数据源候选中accessLevel及dataWareHouse是服务端属性，客户端标签不授予资源权限。成员树组合ID只服务控件，memberIds提交用户稳定ID。
- pageSize=20是客户端初始值；4条样本、跳页max=1均不是容量或配额。name/spaceRemark/spaceObjective的客户端上限分别为100/1000/1000，不证明后端唯一性或字节计数。
- 查询与返回恢复必须校验会话范围；业务缓存不能只用路径作为跨账号隔离键。切换、撤销和过期后清除不再获准的数据。

### 公共请求与响应合同

服务前缀优先取运行配置MODULE_URL_PREFIX.dopSpace，否则取/dop/space；公共客户端的API_BASE_URL路径部分为/back。下文使用该配置对应的相对组合路径，环境覆盖前缀时统一替换，不能硬编码部署地址。commonUser前缀同理采用/common/user。GET输入放params；POST/PUT/DELETE输入放data，无输入时包装器传{}，JSON对象经公共客户端序列化。默认Content-Type为application/json;，withCredentials=true。公共拦截器按存在的会话材料附加CSRF、令牌和签名头；本文只规定头的用途，不保存值。

Axios接受的非202正常响应返回response.data；HTTP 202按业务错误处理，提取msg并reject。业务码1002清会话令牌并转登录，1003转无权限，1109转改密，1012刷新。错误处理不允许自动重放创建、修改、删除或空间切换。实际成功body和业务码必须由服务端合同明确，不能把任意HTTP 200或空响应判为持久化成功。

超时先取匹配路径的非负REQUEST_TIME_OUT规则，再取请求number类型timeout，缺少数值时回退20000ms；0未被排除，不代表已经设置有限超时。实现按SPACE-NFR-004提供有限超时与结果核查。前缀、错误分支及序列化定义不等于运行环境已验收。

## 5. 主要业务流程

发现空间 → 查询/分页 → 查看配置；创建基础空间 → 独立配置成员/数据源 → 回读授权结果；编辑基础与配置分别提交；删除前确认影响与保护；顶部切换前确认会话变化。各动作独立验权，列表出现对象不自动赋予写入、加入或切换权限。
