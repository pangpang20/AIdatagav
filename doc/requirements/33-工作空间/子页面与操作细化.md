## 3. 功能需求

### SPACE-500 工作空间管理

**业务目的**：提供完整筛选、卡片、分页及按权限显示的操作入口，使用户明确对象与当前会话。

**操作与规则**：

1. 加载列表，保持顶部当前空间、租户和左侧导航可识别。
2. 按名称、类型筛选或重置，操作页大小/页码；结果与当前条件一致。
3. 选择显式查看/维护入口，按主文目标执行；返回时恢复有效条件。

**结果与异常处理**：列表失败、主体失败、空结果与无权限分开；创建入口隐藏不等于产品取消创建；4条样本不构成配额。

**开发处理细则**：此编号是操作页面拆分，不再定义第二套查询API。字段和控件使用主文合同；DOM的readonly是选择控件输入属性，不表示类型业务禁选。

#### 3. 业务流程与异常分支（SPACE-500）

进入列表 → POST分页 → GET主体 → 渲染卡片动作 → 查询/翻页/打开目标 → 返回。返回缓存带账号、租户、空间边界；加载错误保留重试入口。创建、编辑、配置和删除各自走独立业务授权，不因卡片可见执行写入。

#### 4. 接口与数据规则（SPACE-500）

列表POST /back/dop/space/workspace/page，body为name、queryCondition、pageRequest；读取datas、total。后续GET /back/common/user/main/subject读取userId、enabledDop，计算isOwn/isEdit。name客户端上限100；pageNo=1、pageSize=20、order按id降序。重置回初始筛选并重新查询。公共前缀、序列化、响应与超时沿用主文第4节。

请求前缀、JSON、Cookie、HTTP/业务判断及超时见第4节公共合同；实际返回DTO、写入成功条件和服务端业务约束交付前须锁定，不自动猜测成功码。
