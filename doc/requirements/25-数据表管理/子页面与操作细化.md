### DTM-500 数据表管理 → 库表资源

**业务目的**：使用者在“数据表管理 → 库表资源”处理对应对象；与其他菜单分别保留查询条件、对象标识和处理状态。

【页面观察】实际路径为`/da-dtm/warehouseResources/warehouseResourcesList`。当前页面标题：数据库信息。

**用户操作与系统响应**：

1. 从“数据表管理 → 库表资源”进入目标页，先核对当前部门、空间及对象范围。
2. 页面提供的输入或选择提示为：请选择数据库名、请选择。其匹配方式、默认值和多条件组合语义待确认。
3. 列表展示：序号、数据库名、数据库IP、数据库类型、表数量、所属部门、创建时间、权限状态。记录条数、名称和当时状态属于样本。
4. 可见操作包括：172.16.1.40、1、MRS-Presto。只有本文件另列并附目标页证据的操作才算已进入；其余仅确认入口可见。

【拟定需求】业务依赖：对象唯一范围、引用关系、生命周期状态、读写权限及生效条件需逐项确认；不能从当前记录样本推定全量规则。

#### 3. 业务流程与异常分支（DTM-500）

1. 进入数据表管理 → 库表资源，读取当前用户、租户/空间和对象标识；页面加载失败时停留在当前页并提供重试。
2. 按字段表填写或选择；缺少必填值、长度越界、格式不合法或确认值不一致时阻止提交并定位字段。
1. 进入数据表管理 → 库表资源，在当前用户、租户/空间及数据权限范围内加载页面；加载失败时保留页面上下文并可重试。
2. 按已观察字段设置筛选条件；未确认的匹配方式、默认排序和状态枚举不得由实现人员推断。
3. 查询成功展示结果及分页；空结果与加载失败、无权限、服务异常分别呈现。
4. 网络超时、服务端校验失败、权限不足和响应异常须明确提示并保留筛选条件；不得把空结果判为故障。
5. 分页、重复查询和条件变更不得串用旧响应；较早请求的迟到结果不能覆盖较新的筛选状态。

| 异常分支 | 预期页面响应（均为拟定，待产品/服务端确认） |
|---|---|
| 空结果/无权限 | 【拟定需求】明确区分无匹配数据与无权访问，不显示为系统错误。 |
| 网络或服务异常 | 【拟定需求】展示失败状态并保留筛选、分页上下文供重试。 |
| 网络超时/服务端错误 | 【拟定需求】展示可理解的失败状态，保留可安全保留的草稿；结果未知时先查询状态，避免错误重试。 |
| 取消/重复提交 | 【拟定需求】取消不产生未确认写入；重复点击在客户端去重并由服务端幂等保护。 |

- 【待确认】不同分辨率、浏览器缩放、长文本、无数据、权限隐藏、接口慢响应和弹窗溢出时的布局规则。

### 授权列表与审批中心按时间并列核对

【页面观察】早期授权管理与审批中心路径的两个样本正文均为数据库信息，不能证明审批目标。本次授权管理仍显示数据库信息；审批中心已正确加载我的待办/我的已办，含申请标题、申请时间、申请部门、申请人员、处理状态及操作列，当前无记录。我的申请另有已提交、待提交及已流转。恢复后的审批列表不能回填为历史错配已有效，也不证明已取得办理表单。

【拟定需求】拟定申请以具体数据库/表、用途、使用范围与期限为对象；申请状态和实际已授予的数据权限分别展示。审批通过后是否自动授权、部分同意、到期撤销与再次申请需形成明确契约，服务端每次访问都校验有效授权。

【待确认】早期正文错配的原因未知；本次审批列表为空，未取得办理详情。授权维护、行列过滤、申请撤回、重复申请、期限边界和回收规则均未验收。
