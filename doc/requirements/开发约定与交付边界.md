# 公共开发约定与交付边界

本文把各模块重复出现的交互、权限、保存和异常处理整理为可实现的公共规则。**以下规则全部为【拟定需求】，未经产品评审，也未在现网执行验收。** 页面明确字段及当前控件属性仍以各模块第4节及第8节证据为准。不能以本约定补造未知业务状态、算法或接口。

## 1. 开发输入与交付条件

| 交付层次 | 可用输入 | 允许交付的结果 | 仍需满足的条件 |
|---|---|---|---|
| 交互原型 | 有效截图、字段表、本文拟定交互 | 标示模拟数据的列表、已采集表单、确认层和异常界面 | 不声称连接、保存、删除、任务或AI已真实实现 |
| 业务开发 | 经评审字段、枚举、状态机、引用/删除和权限规则 | 对应范围的真实读写功能 | 独立评审接口契约、持久化/事务和迁移方案；不得猜测现网API |
| 生产验收 | 已实现功能与授权测试环境 | 可复现的主流程、失败、并发、隔离与恢复结果 | 用例实际执行并记录结果；文档检查不能替代业务验收 |

尚未取得目标页面的对象只登记待确认功能，不能因为菜单存在就生成一套标准CRUD。工单、运行实例、日志等也不能默认允许人工新建、修改或删除。

## 2. 字段与对象标识

- COM-001【拟定需求】：每个对象使用稳定标识；关联字段保存标识及必要版本，显示名称不作为唯一定位依据。输入与输出同名字段必须有区域作用域，例如输入schema和输出schema。逻辑标识不等于已确定数据库表或列名。
- COM-002【拟定需求】：字段定义须区分可编辑、只读/禁用、系统生成和条件出现。禁用字段由服务端从受信上下文取得或校验，不因客户端禁用就认为安全。缺少星号的采样不能证明字段可选。
- COM-003【拟定需求】：建议名称/编码去除首尾空白后判断必填；保留中间空白。描述可保留换行；密码、SQL、表达式、路径、文件内容不自动去除空白。各模块需确认例外；未经评审不能悄悄改变已有内容。
- COM-004【拟定需求】：建议字符串上限按UTF-16代码单元计数，以便与浏览器maxlength一致；普通中文字符占1，部分扩展字符/emoji占2。界面计数、请求校验和存储必须统一。页面maxlength只证明当时控件属性，**不能据此断言后端有同一限制**。若产品选择其他字符计数口径，须同步调整字段表与验收。
- COM-005【拟定需求】：数值必须另列整数/小数、单位、精度、上下界、0与空值含义及组合约束。不得把text控件字符上限当作数值上限。未明确单位、动态上限或算法的字段在开发前决策。
- COM-006【拟定需求】：只使用已经确认的枚举值；下拉样本不证明全量枚举。关联候选按当前权限获取并保存标识；显示已删除、失权或停用的旧引用时明确失效原因，不自动替换成其他候选。

## 3. 查询、分页和返回恢复

- COM-007【拟定需求】：点击查询后记录“已提交条件”；输入框尚未提交的内容与结果条件分开。连续查询只采用最后一次有效请求结果，过期响应不得覆盖新结果。失败时保留输入并标示旧结果对应的旧条件。
- COM-008【拟定需求】：建议文本条件采用名称包含匹配，关联标识/枚举采用精确匹配；这是待评审默认值，不能当成现网事实。大小写、空白、模糊转义和全角字符规则逐对象确认。重置清空可选条件并恢复页面初始默认值；初始默认未知时先补定义。
- COM-009【拟定需求】：变更已提交条件回到第一页；页大小可选值、默认排序和排序并列规则逐对象确认，不从样本数量推导。列表与总数使用同一权限与筛选口径。删除最后一条后定位仍存在的有效页。
- COM-010【拟定需求】：从列表打开详情/编辑再返回，恢复已提交条件、排序和页码；数据变化后重新查询当前有效页。直接地址进入且无来路时返回本模块列表。切换空间或退出会话清除前一上下文的结果和选择，不复用跨空间缓存。

## 4. 状态与失败处理

下列为应用层语义，**并非已观察到的现网HTTP状态码或错误码**。正式接口可映射到经评审的协议。

| 状态/建议标识 | 界面与业务处理 | 是否可立即重试 |
|---|---|---|
| 加载中 | 展示加载和当前请求范围；同一提交防连点 | 查询可重新发起；写入不重复发起 |
| 成功 | 结果与对象标识、版本对应；刷新读取一致 | 无须重试 |
| 空结果 | 显示无符合条件的数据，保留条件与重置入口 | 可调整条件 |
| VALIDATION_FAILED | 对应到具体字段/子项并说明原因，保留输入 | 修正后可重试 |
| PERMISSION_DENIED | 不展示无权详情，提示权限不足；不扩大查询范围 | 权限变化后再试 |
| OBJECT_NOT_FOUND | 表示目标已不存在，返回列表 | 先刷新对象 |
| REFERENCE_BLOCKED | 列出当前用户有权查看的引用与处理方向 | 处理引用后再试 |
| VERSION_CONFLICT | 保留本地输入，展示版本变化并要求重载核对 | 核对后以新版本提交 |
| DEPENDENCY_UNAVAILABLE | 连接/依赖不可用，保留配置且区分加载失败与无候选 | 用户重选或明确重试 |
| RESULT_UNKNOWN | 写入超时/断网，显示结果待核实，按操作标识查询结果 | 未核实前不创建第二次写入 |
| SERVICE_FAILED | 明确操作失败；保留可恢复输入并给重试入口 | 确认未成功后重试 |

COM-011【拟定需求】：可见错误包含业务说明、可执行的下一步和追踪标识；不回显凭据、Token、内部堆栈或无权对象。多个独立指标可部分失败，失败值不能填0伪装成功。网络失败不解释为数据为空。

## 5. 新增、修改、取消与并发

- COM-012【拟定需求】：新增输入为本表单字段和已定义子项；修改还包含对象标识及读取时版本。输出至少有对象标识、最新版本和明确结果。主记录和子项应作为一个业务结果提交；实现可采用事务或补偿，但不能遗留界面宣称成功而子项失败的记录。
- COM-013【拟定需求】：提交时按钮进入处理中，客户端和服务端共同防重复。一个业务意图使用同一操作标识；同标识且同内容返回同一结果，同标识而不同内容返回冲突。操作标识有效期、结果查询和并发协议须在接口契约中评审。
- COM-014【拟定需求】：取消未提交编辑丢弃本次输入，不发送业务保存；有未保存变更时提示放弃。提交进行中关闭窗口不等于服务端已取消，须在重新进入时查询结果。明确失败保留输入；会话过期后的恢复不得把秘密存入浏览器长期存储。
- COM-015【拟定需求】：修改以读取版本进行条件更新；版本冲突不得静默覆盖另一操作者的修改。保留本地差异，由用户重载比较后决定再次提交。关联对象版本改变时重新校验已选子项。
- COM-016【拟定需求】：多步需求与报告模板的“下一步”只表示推进当前流程。草稿何时持久化、步骤级校验、回退保留、最终提交、取消草稿和临时附件清理须逐模块定义，**目前是阻断项**。不能套用单页表单规则声称首步已创建业务单。

## 6. 删除、移除及任务操作

- COM-017【拟定需求】：删除确认按稳定标识定位，展示目标、引用和影响；取消不发送业务删除。删除前重查权限、版本、引用及运行状态；未定义删除范围时只可实现确认界面，禁止自动级联外部表、文件、Broker Topic或历史报告。
- COM-018【拟定需求】：明确区分删除平台定义、移除个人关联、停用、撤销授权、终止运行和清理历史。各对象须列逻辑/物理删除、回收/保留期、审计、引用保护及恢复规则，不能仅凭“不能恢复”文案选择物理删除。
- COM-019【拟定需求】：任务定义、发布版本、调度开关和运行实例分别建模。保存定义不默认执行；启动、停止、重跑、补数、发布与启停调度各有独立权限、确认、输入和结果。任务状态机、断点、重试范围、幂等和超时必须在模块规则确认后实现。
- COM-020【拟定需求】：历史实例绑定实际执行的配置/规则版本和数据范围；修改定义不改写历史结果。暂停调度不等同停止正在运行的实例。后台活动出现不能作为“本次打开页面触发任务”的证据。

## 7. 附件和凭据

- COM-021【拟定需求】：附件记录标识、原文件名、大小、类型、上传状态和所属对象；只有上传成功且校验通过的文件计入有效附件。扩展名、内容类型与内容检查分别处理。容量口径、文件数、超时、清理和版本保留按各模块确认，不能从单个样本推导。
- COM-022【拟定需求】：选择文件不等于业务记录已保存。取消表单后清理临时文件需可重试且不误删已被提交引用的文件；提交超时先核实归属。下载/预览重新验权，文件名不能充当直接可访问的存储地址。
- COM-023【拟定需求】：凭据采用受控秘密引用。编辑必须区分保留原值、替换和明确清空；空框不自动清空已存秘密，回显不返回原秘密。具体密文存储、传输、审计和过期策略需技术与业务评审。本任务文档与截图不保存秘密输入值。

## 8. 权限与可访问性

| 操作 | 建议权限粒度【拟定需求】 | 必须由业务确认的范围 |
|---|---|---|
| 列表/详情 | 查看对象及字段 | 本人/部门/空间/租户/跨域可见范围 |
| 新增/修改 | 维护对象 | 对象归属、禁用字段、关联候选与状态条件 |
| 删除/移除 | 删除对象或解除关联 | 引用/运行保护、外部资源和历史保留 |
| 审批/发布/授权 | 独立办理权限 | 发起人与审批人是否分离、期限、撤销 |
| 执行/启停/重跑 | 独立运行权限 | 来源和目的访问权、生产范围及确认 |
| 导出/下载/AI使用 | 独立的数据使用权限 | 行列范围、使用用途、外发和留存策略 |

COM-024【拟定需求】：菜单隐藏只是交互；直接地址、对象标识、分页总数、关联候选和导出均需服务端验权。AI可见范围不得大于当前用户。切换租户/空间后使旧请求失效，旧响应不得进入新上下文。

COM-025【拟定需求】：控件有可读标签，错误关联到字段；键盘可到达主要操作；打开对话框聚焦内部、关闭后返回触发点；加载/错误变化可被辅助技术感知。颜色之外同时显示状态文字。缩放、焦点顺序和屏幕阅读器用例需要真实执行后才能声称通过。

## 9. 接口和数据模型交付检查

每个进入业务开发的功能需另行完成：请求/响应字段类型与必填、枚举和单位、权限、分页排序、幂等与版本、错误分类、结果未知恢复、关联/删除范围、事务/补偿、审计和留存。所有物理表/字段、endpoint和错误码须在正式契约中决定；本文不规定未知现网接口。

AI扩展采用同样交付边界，详见[AI能力规划](./AI能力规划.md)。开发顺序与本版能交付的范围见[开发就绪审查](./开发就绪审查.md)。
