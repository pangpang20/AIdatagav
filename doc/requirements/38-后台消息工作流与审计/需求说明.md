# 后台消息、工作流与审计需求说明

<!-- 业务规格格式:plain-v1 -->

## 1. 业务目标与入口

从后台管理进入监控、消息、工作流及日志管理。维护告警、消息分类/渠道/模板、消息投递及公告、本人相关工单、业务分类、流程模型/版本、实例与表单，按授权读取操作/登录审计。角色名称与可管理范围采用批准矩阵；本文不按一个采样账号扩大为全局管理权限。

读取均区分初始化、有效空数据、无权、失败及格式错误；写入仅在有授权的编辑/办理分支显式触发。失败终结忙碌，保留安全上下文；取消零写入。未取得后端业务成功合同的动作不能仅以Promise resolve提示业务完成。

## 4. 公共接口、字段与响应约定

路径表为已查API包装器默认前缀。模块通过bcab接收宿主getRequestInstance，MODULE_URL_PREFIX可覆盖commonMsg、commonMonitor、commonLog、commonWorkflow；默认分别为/common/msg、/common/monitor、/common/log、/common/workflow。消息包装器再拼/msg，故路径确为`/common/msg/msg/...`，不可擅自去重。宿主baseURL与网关前缀另行组合；既有宿主默认加`/back`，部署联调必须记录最终相对路径，不能将静态路径称为认证Network结果。

GET参数经公共request放params，其余放data；普通JSON请求与DELETE body保持类型。消息重发调用端已经JSON.stringify，最终序列化须与后端明确是字符串还是数组；禁止擅改为逗号串。列表组件读取datas/total，候选和历史部分直接用数组；无真实响应不能补造code=0或success=true。

公共历史传输链返回response.data，rawData分支可返回原response，配置NETWORK_ERROR_CODE触发异常映射；局部then并不充分证明持久化/投递/流转完成。flow模块接收宿主实例的证据与公共宿主片段相互关联，但当前覆盖配置、Cookie属性、CSRF/令牌和错误码的实际生效值仍须部署合同验证。超时可按配置/调用覆盖，20秒兜底不能作为每条请求有限超时保证。

目标处理：字段校验阻止请求并关联错误；认证过期进入统一会话恢复，权限拒绝不按空列表处理；5xx/断网/解析失败结束loading。写超时显示结果未知，查询同一对象/批次/实例及审计后才允许人工重试。禁止无界透传读回对象、自动重发通知或静默覆盖新版本。

## 5. 跨页面流程

管理列表定位稳定ID → 读对象/依赖 → 按动作及状态判权 → 编辑安全草稿 → 校验和确认影响 → 单次写入 → 确认业务结果 → 回读同一对象/版本 → 恢复来源筛选。批量选择仅代表实际已选ID，不隐式包含所有匹配页；分页/切换清理失效选中项。

工作流分类→模型→部署版本→表单快照→实例→任务的引用需后端保持一致。已部署/运行实例引用保护、节点配置与模型分别保存的部分成功、队列重试去重及版本冲突必须显式处理。只读模型/历史图不因点击或关闭保存；我的消息打开已读副作用单独授权。
