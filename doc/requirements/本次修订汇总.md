# 本次修订汇总

修订日期：2026-10-22。范围为数据中台现有页面资料的业务需求重写、逐操作细化、用户菜单补充与AI能力规划。本轮没有新增浏览器操作，没有修改应用业务数据或执行任务。

## 1. 本次解决的问题

原文把路由、控件属性和点击结果放在主要位置，读者不容易理解业务目标，也难以判断系统应怎样处理输入。现将35份模块正文按业务目标、适用范围、操作步骤、处理规则、结果与异常、字段、流程、验收及待确认事项组织；每项已展开功能增加开发处理细则和证据来源。

页面事实继续使用【页面观察】【操作观察】【页面文案】标记；新增设计使用【拟定需求】；证据不足使用【待确认】。控件长度只证明采样时的前端属性，页面说明只证明产品当时的承诺，均不作为后端实现或测试通过的结论。

原35份正文及总览转存为调研附录，仅按要求将指定部署地址规范化为应用路径，便于追溯。原截图保留；业务样本保留可见原文，不猜测页面已隐藏的内容。

115个对象中，50个有列表或卡片证据，3个有详情，27个有新增页面，12个有编辑页面，10个有删除确认，另有1个删除入口请求被阻断。各类范围重叠，不能相加作为对象覆盖数。65个对象目前只有父页或导航线索。

尚未取得目标页的操作不能仅凭按钮名称补造字段、状态或删除保护。相应编号仍在模块待确认清单和逐操作索引中，后续可逐项补采、评审和验收。当前没有把“打开新增/编辑/确认页”写成“真实保存/修改/删除已验证”。

| 入口 | 本次拟定处理范围 | 开发前必须补齐 |
|---|---|---|
| 基本信息 | 本人资料读取、批准字段编辑、保存回读、并发/取消/失权 | 身份来源、真实字段、只读/可改范围、格式及同步 |

## 5. AI能力汇总

以下优先级仅为建议评审顺序，不是现网能力或批准排期。

| 场景 | 建议优先级 | 输出及人工确认 |
|---|---|---|
| 需求申请补全与相似需求检索 | P1 | 申请草稿、相似依据；申请人及受理人确认 |
| 元数据释义与标准匹配 | P1 | 字段解释、候选标准及版本；治理人员确认 |
| 源目标字段映射 | P1 | 映射草稿、类型损失和冲突提示；开发人员确认 |
| 自然语言澄清与SQL草稿 | P2 | 待确认口径和SQL草稿；受控查询服务独立校验 |
| 质量规则建议与异常解释 | P1 | 规则草稿及异常证据；治理人员确认，检测引擎计算 |
| 分类分级建议 | P2 | 候选等级、依据和歧义；复核人员决定 |
| 目录语义检索与资源推荐 | P1 | 有权资源和来源；使用者核对后按原流程申请 |
| 指标口径与标签草稿 | P2 | 公式、粒度、周期及人群歧义；业务负责人确认 |
| 报告解读与摘要 | P1 | 引用数值与摘要草稿；评价人复核发布 |
| 调度及运维日志归因 | P2 | 候选原因和排查建议；运维人员核实与决定 |

建议先对元数据释义、目录检索、需求补全验证价值；字段映射、质量建议和报告摘要需先明确资料版本及评价方法；查询、分类分级、指标标签和运维归因依赖更多业务规则。

所有场景均已列明授权输入、输出与依据、流程、采纳边界、异常恢复、依赖和验收。AI采纳只进入待保存草稿，不自行保存、审批、发布、授权、改密或启停任务。模型部署、资料外发、接口、成本、时延及质量阈值尚待批准，58条验收全部未执行。详见[AI能力规划](./AI能力规划.md)。

## 6. 能否直接交给AI开发

**目前可用于明确范围的界面和模拟交互原型，仍不足以让AI无需补充地完成整套生产系统。** 文档中已按模块列出对象边界、输入依赖、处理细则与验收，但以下生产契约仍缺证据或产品决策：

1. 65个导航对象及其他未观察操作的真实目标页面、子表、字段、枚举、必填和边界。
2. 需求/审批/发布/任务的状态机、可操作角色、失败补偿、撤回和重复处理规则。
3. 账号、主部门、租户、空间及行列数据权限，跨模块上下文与授权撤销。
4. 实体标识、唯一作用域、关联删除保护、版本冲突、审计及保留周期。
5. 接口输入输出、分页排序、错误码、幂等与结果核实，以及算法、统计口径和运行参数。

建议按基础维护对象→数据源及集成子配置→审批和任务生命周期→目录/指标/安全/评价算法的顺序评审；每次将一个明确业务对象补齐到可执行验收，再确定接口和真实持久化。不能把公共开发建议当成已获批准的业务规则。
