# 后台配置管理需求说明

<!-- 业务规格格式:plain-v1 -->
<!-- bcf:reviewed-spec-v1 -->

## 1. 业务目标与角色

后台管理→配置管理，从`/module-common/index`进入。维护应用、系统入口、平台分组/分类/排列、分类字典、特殊日期和许可证；后台数据源六个导航目标复用数据源管理域。操作者在批准角色和对象范围内分别获读取、维护与高影响动作权限。

“系统管理”配置页`/module-common/config/system/list`与后台系统管理分组不同；应用、系统、平台、平台分类、字典分类及许可产品分别建模，禁止按同名混为一个对象。

## 2. 业务范围

| 需求 | 业务对象及独立操作 |
|---|---|
| BCF-001 | 查询和创建应用 |
| BCF-002 | 修改外部应用与接入场景 |
| BCF-003 | 维护系统入口、介绍与资料 |
| BCF-004 | 维护平台分组与系统排列 |
| BCF-005 | 维护分类字典项 |
| BCF-006 | 维护特殊日期 |
| BCF-007 | 查看许可证与更换入口 |
| BCF-008 | 通过后台访问数据源管理 |

应用详情凭据查看/轮换、系统手册即时上传、平台分类与初始化、许可证手动激活均为独立分支；资料保存不隐式替代它们。数据源驱动、连接、部门范围及API/Kafka维护以[数据源管理](../07-数据源管理/需求说明.md)为唯一业务规则入口。

#### 3. 业务流程与异常分支（BCF-001）

1. 进入列表 → POST按obscureName/appType和pageRequest查询 → 以行id进入详情或编辑，新增不带旧id。空数据、拒绝和解析失败分别显示。
2. 新增按appType/场景构造字段；外部joinType数组转逗号字符串，内部删除joinType。URL隐藏残值、casService嵌套对象和appKey不能无边界透传；白名单及null保留/清除语义按BCF-DEP-01/03固定。
3. 名称100/101、KEY100/101、纯空白、中文/符号KEY、重复KEY和并发创建分别拒绝或成功回读；唯一范围和大小写规范以批准服务端合同为准。创建超时先按KEY及审计核查，禁止自动重放。

依赖失败、字段错误、失权、引用/重复/版本冲突、会话过期及技术失败分别显示；不能把失败当空数据。写入结果未知先核查同一对象及审计，不无条件重试。关闭或离页对已经发送的副作用不承诺回滚。

#### 3. 业务流程与异常分支（BCF-002）

1. 按id读取应用 → 将joinType字符串拆数组、缺失casService补对象 → 编辑场景和有效URL → PUT同一id → 回读配置，保持身份不变。
2. 凭据查看POST /app/realSecret发送{id,userPwd}，返回值用于当前详情secret。失败清密码、保留应用身份供核对；显示遮蔽不能保证浏览器调试无法读到用户输入或已授权返回值。
3. 轮换先确认 → GET refreshSecret/{id} → 安全显示当前新值及提示核实接入端；响应丢失只提供核查途径，不再次轮换。撤销旧值、生效窗口及并发版本须取得BCF-DEP-02/03合同。

## 4. 公共接口、字段及响应规则

模块parentdata注入宿主getRequestInstance；服务前缀优先MODULE_URL_PREFIX覆盖，缺省commonApp=/common/app、commonUser=/common/user、commonDict=/common/dict、commonCalendar=common/calendar、commonOss=/common/oss、commonLicense=/common/license。日期前缀原文缺少首斜线，宿主request会去掉路径首斜线，和API_BASE_URL加`/back`组合后默认日期列表为POST `/back/common/calendar/calendarspecial/page`，系统列表为POST `/back/common/app/system/page`。部署覆盖须在联调核对，表中统一显示相对路径。
