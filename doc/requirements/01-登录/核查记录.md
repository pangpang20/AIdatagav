## 核查结论

继续检查了登录组件、非空校验工具、Element UI勾选组件、公共请求客户端、签名工具和两份部署配置。原先不清楚的网关前缀、JSON序列化、协议值类型、账号空白处理、业务错误入口及1109路由现已查明；以下结论均为静态定义核对，不是现场请求或服务端验收。

## 现有实现与目标规格差异

下列要求为目标修正或明确化，不能因为正文不再加调研标签就声称原系统已实现。未修改目标应用，仅更新需求、证据和文档工具。

| 正文规则 | 当前证据中的实现 | 目标及验收归属 |
|---|---|---|
| trim后非空 | 先非空、后trim；纯空格存在校验缺口 | trim后重新校验，阻止空账号；AUTH-AC-005 |
| 公钥就绪才提交 | 表单出现不等待公钥，公钥读取缺少本页catch | 公钥门控与重取，不回退明文；AUTH-AC-006 |
| 本地异常恢复 | requestLogin组装参数时同步加密，异常不在该请求Promise catch中 | 统一try/finally恢复锁与按钮；“登录准备失败，请重试”为目标文案，非原语言包文案；AUTH-AC-006 |
| 点击与Enter共用请求锁 | 按钮绑定loading，但handleLogin没有独立if(loading)拒绝再次进入 | 所有入口单次认证锁；AUTH-AC-007 |
| 条件项读取失败阻断 | 验证码和协议请求finally也增加status；失败可能留下隐藏条件项，未取运行结果 | 区分读取失败与明确关闭，恢复后才允许提交；AUTH-AC-006 |
| 失败草稿与验证码 | catch清loading，除1109外刷新图片；没有显式清除旧authCode | 保留账号和协议、清除被刷新图片对应的旧码；密码重新聚焦仍清空；AUTH-AC-006、007 |
| 离页清理密码 | 已检查片段没有明确离页清理逻辑；不能从DOM替换断言模型明文已清 | 组件离开/销毁清理密码草稿；AUTH-AC-007 |
| 状态与适配 | 具备loading与CSS媒体分支；未取得公钥失败、慢请求、窄屏/200%运行画面 | 加载/错误反馈可操作，表单与协议框不溢出、键盘可达；AUTH-AC-003、006 |
| HTTPS及服务端安全 | 客户端RSA和签名可读，不能证明TLS、密码哈希、限流、会话撤销与审计 | 属于安全交付要求，需下节外部证据；AUTH-AC-001、002 |
| 有限超时 | 公共拦截器接受非负路径值及number类型请求值，0不被这段逻辑排除；未取得运行时实际值 | 认证及初始化使用有限统一超时，无覆盖时以20000ms为目标；超时1秒内恢复；AUTH-NFR-007、012 |
| 非功能验收基线 | 静态文件和历史截图均不提供性能、容量、月度可用性或完整兼容性实测结论 | 按用户补充要求制定质量目标与复现条件；AUTH-NFR-001至013，全部未执行 |

密码目标为正常请求不含明文、不会把密码写入存储或日志、加密失败不提交。不能阻止控制本人浏览器的使用者在加密前读取自己输入的明文；禁用F12、右键或把DOM值换成密文均不能实现此承诺。adq-token存储沿用现有客户端行为，不伪称该令牌存储方案已通过独立安全审计。

## 非功能指标的来源与执行边界

AUTH-NFR-001至013为用户本次要求补充的开发质量规格，不是从界面推导出来的原系统保证。正文分别给出可判定目标和验收方法，独立于七条既有功能验收；编号不冒用AUTH-AC，也不改历史登记。

- TLS 1.2及以上、单向密码哈希、会话隔离、服务端限流、审计和无障碍等属于新增交付要求。客户端RSA算法和超时分支有静态依据；不以这些片段证明后端安全已达标。
- 首屏P95≤3秒、反馈P95≤100ms、100个并发虚拟用户、认证P95≤2秒/P99≤5秒、非预期失败率≤0.1%、月度可用率≥99.9%及相关测试环境是本次制定的目标验收基线，未进行性能压测、月度监测或应用验收，不能对外声称为实测能力。
- 20秒为拦截器无number值时的代码回退，也是本次有限超时的目标默认值；不把代码回退等同于当前生效配置。性能响应目标、请求超时预算和月度可用性分别计算。
- Chrome/Edge版本、Windows平台、分辨率、窄屏和200%缩放、对比度及辅助技术验收是目标覆盖矩阵；历史E002只覆盖1440×1000的一次页面样本。
- 验证码无障碍替代方式、服务端限流阈值/恢复条件、认证Cookie配置、日志留存及请求关联能力需结合下节服务端材料落地。正文不新造接口、请求头或业务码；不可用当前单账号资料推定全局策略。
