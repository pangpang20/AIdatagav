# 数据中台业务总览与跨模块流程

## 业务目标与范围

平台以数据需求为起点，提供接入、开发、治理、共享、使用和评价相关工作入口。申请人说明需要什么数据、用于什么场景；维护人员配置来源和处理关系；使用者查找资源或申请服务；治理人员检查质量与安全；运维人员关注运行状态。

这是依据现有模块整理的产品范围。各环节是否必须串行、是否自动流转、由谁负责仍需业务负责人确认；现有页面不能证明已形成完整闭环。

实际导航为需求管理、数据开发、数据一体化、数据资产、数据评价、后台六组，另有登录和工作台，原登记35个应用模块。本轮实际打开右上角用户菜单及后台，新增系统、配置、消息工作流与审计3份专项；它们描述后台职责，不代表又增加3个独立应用。信息架构见[模块矩阵](./README.md#模块覆盖矩阵)，逐链接进展见[全链接核查](./全链接核查清单.md)。

## 使用角色

以下为【拟定需求】分工，供权限评审，不是从单账号推导出的既有权限。

| 角色 | 主要工作 | 待确认边界 |
|---|---|---|
| 需求申请人、受理人 | 提出需求/咨询，归集项目并跟踪协作 | 部门可见范围、办理与申请关系、审批及撤回 |
| 数据接入和开发人员 | 维护来源、同步任务、模型、构件和流程 | 编辑与运行分权、凭据使用、生产操作范围 |
| 数据治理人员 | 管理标准、元数据、指标、标签和保护策略 | 审核发布、版本引用、敏感字段访问 |
| 资源使用者、服务提供者 | 查找、申请、提供或调用数据 | 审批、授权期限、订阅及到期回收 |
| 检测与评价人员 | 组织检测、评价、AI辅助配置和模板 | 执行、复核、评分及报告可见范围 |
| 平台和运维人员 | 管理空间、监控、告警和平台配置 | 租户隔离、管理员权限及操作审计 |

## 核心业务流程

### 1. 提出并受理需求

1. 申请人按部门和项目提出需求，说明业务用途和预期成效。
2. 申请按需求信息、基础数据、数据库信息、附件四步组织；目前只充分取得第一步字段。
3. 【拟定需求】受理人确认数据范围、交付内容和责任后安排实施。
4. 【待确认】后续字段、草稿、受理/退回/补充状态、任务生成及完成条件。

对应：[业务需求管理](./03-业务需求管理系统/需求说明.md)、[数据调研](./04-数据需求管理/需求说明.md)、[我的工单](./06-我的工单/需求说明.md)。

### 2. 接入来源并配置处理任务

1. 维护人员登记数据库、API或Kafka来源，明确连接及来源定义。
2. 配置表、库、API、文件或实时同步任务，说明来源、目的、字段处理和通道控制。
3. 【拟定需求】需要协同执行的任务组织为流程，确定依赖与调度策略。
4. 【待确认】引用标识、保存是否触发执行、任务与调度状态、失败重试和恢复。

对应：[数据源](./07-数据源管理/需求说明.md)、[集成采集](./08-数据集成采集/需求说明.md)、[编排调度](./09-任务编排与调度/需求说明.md)。打开配置页不代表连接或同步成功。

### 3. 建立治理规则与资源描述

1. 通过标准、模型、元数据、指标和标签描述数据对象及含义。
2. 安全保护、目录等模块提供相应管理入口。
3. 【拟定需求】对象发布或变更时，向引用方提供明确版本和适用范围。
4. 【待确认】标准与物理字段、元数据与目录、指标与来源、标签与资产的关联和变更传播。

对应：[标准](./11-数据标准管理/需求说明.md)、[建模](./10-规范化数据建模/需求说明.md)、[元数据](./19-元数据管理/需求说明.md)、[指标](./20-指标管理/需求说明.md)、[标签](./21-标签管理/需求说明.md)、[安全保护](./24-数据安全保护/需求说明.md)。

### 4. 查找、申请和使用资源

1. 使用者从目录、门户、服务或查询入口查找数据。
2. 【拟定需求】需要申请的数据应说明用途、审批责任、范围与期限，获授权后使用。
3. 【待确认】目录发布、共享交换、服务注册、门户展示与授权生效的关系；同名不证明同源或相同统计口径。

对应：[目录](./14-目录管理系统/需求说明.md)、[交换](./15-数据共享交换/需求说明.md)、[服务支撑](./16-数据服务支撑/需求说明.md)、[门户](./17-数据服务门户/需求说明.md)、[数据表管理](./25-数据表管理/需求说明.md)。

### 5. 检测、评价和报告

1. 检测人员选择对象与规则，组织标准、安全或质量检测。
2. 评价方案以指标、任务和模板为关联对象，报告模板提供内容载体。
3. 【拟定需求】评价使用明确的数据版本与评分规则，报告可追溯到对象、任务和模板版本。
4. 【待确认】检测结果是否自动流入、权重、缺失项处理、生成、复核与发布。

对应：[标准检测](./27-数据标准检测/需求说明.md)、[安全检测](./28-数据安全检测/需求说明.md)、[质量检测](./29-数据质量检测/需求说明.md)、[评价](./30-评价管理/需求说明.md)、[模板](./32-报告模板/需求说明.md)、[AI辅助](./31-AI数据智能辅助/需求说明.md)。

## 用户菜单和AI扩展

用户截图及现场展开均确认右上角有基本信息、修改密码、设置主部门、后台管理、退出登录。已打开的三个账号弹窗及后台目标路径、字段、约束见[用户菜单补充需求](./02-工作台/用户菜单补充清单.md)。身份策略和真实提交效果仍待确认，退出登录未执行。后台子业务分别见[系统管理](./36-后台系统管理/需求说明.md)、[配置管理](./37-后台配置管理/需求说明.md)、[消息工作流与审计](./38-后台消息工作流与审计/需求说明.md)。

【拟定需求】新增10个AI场景见[AI能力规划](./AI能力规划.md)，采用授权资料、可追溯建议、人工逐项采纳和原业务保存/执行分离的流程。模型不可用时保留人工流程。AI不能扩大数据权限，不能直接修改密码、主部门、业务记录或执行任务。

逐功能实现边界见[开发约定](./开发约定与交付边界.md)与[开发就绪审查](./开发就绪审查.md)。当前可支持部分交互原型，不能支持未经评审的全平台生产开发。

## 公共业务规则

下列均为【拟定需求】，需评审后在授权测试环境验收。

| 编号 | 业务要求 | 需明确的规则 |
|---|---|---|
| COMMON-001 | 查询区分加载、空结果和失败；失败保留条件并允许重试 | 匹配方式、分页排序、重置及默认条件 |
| COMMON-002 | 必填、格式、长度、数值及关联条件有明确提示，前后端一致 | 唯一范围、单位、边界、动态及组合约束 |
| COMMON-003 | 读写按角色、部门、空间、租户和资源授权 | 权限矩阵、接口鉴权、直接地址访问 |
| COMMON-004 | 保存明确对象与结果，失败保留可恢复信息，防止重复生成 | 草稿、并发、重复请求、刷新和审计 |
| COMMON-005 | 区分删除、移除、停用和物理删除，提示影响并保护引用 | 确认、运行中对象、级联、历史与恢复 |
| COMMON-006 | 分别呈现创建任务、保存配置、发布和运行的状态及影响 | 启停、失败重试、去重、断点与取消 |
| COMMON-007 | 取消、返回、多步回退有明确去向与内容保留规则 | 列表进入、直接地址、刷新及跨模块来路 |
| COMMON-008 | 统计注明对象、单位、范围、更新时间及去重口径 | 同名指标、分母、时间边界与刷新一致性 |
| COMMON-009 | 账号、连接凭据和敏感结果按授权使用并记录必要审计 | 传输保护、凭据保留/清空、会话过期 |
| COMMON-010 | 标签与错误对应，键盘可达主要操作，对话框焦点可恢复 | 对比度、阅读顺序、缩放和辅助技术 |

## 优先待确认事项

| 优先级 | 业务问题 | 依据与下一步 |
|---|---|---|
| P0 | 用户身份、密码、主部门和退出策略 | 三个弹窗及后台功能树已取得现场证据；继续补后台深层分支、身份协议与退出/会话撤销策略 |
| P0 | 谁能看、维护、审批和运行什么 | 单账号不足以建立权限矩阵，由产品与系统负责人确认 |
| P0 | 保存、删除、任务操作的完成标准和影响 | 目前主要为开页和取消，先明确结果、引用保护与审计 |
| P0 | 需求、审批、供数、评价报告的责任与结束条件 | 不由按钮名推断流程，补访谈及目标页 |
| P1 | 65个导航对象的实际业务范围 | 逐项缺口保留编号，从真实菜单补页 |
| P1 | Topic、API参数、映射等子配置规则 | 数量、重名、编码、连接错误及取消尚需定义 |
| P1 | 数值和文件限制的真实业务含义 | 并发1—10来自提示；MB/S与M/s冲突；确认单位与后端规则 |
| P1 | 元数据编辑取消去向 | E102/E103曾到其他模块，保留返回异常，不判通过 |
| P1 | 删除与移除的确认和影响是否一致 | F153曾直接发起被阻断的请求，不能概括所有操作均有确认 |
| P1 | 目录、门户、资产和运营的数据关系 | 同名资产目录指标不同，分别确认口径与同步 |
| P2 | 附件、兼容性、无障碍和恢复验收范围 | 规则明确后补测，现有资料不能证明满足 |
