#### 3. 业务流程与异常分支（SMS-105）

1. 【页面观察，来源：前端源码】选择单个/多个流程并进入scheduleSetting。
2. 【页面观察，来源：前端源码】按定时/事件/单次策略填写；源码事件校验按errors对象及分支判断，必须实测各缺项组合。
3. 【页面观察，来源：前端源码】单项保存策略；批量保存增加parseInt转换后的ids。
4. 【页面观察，来源：前端源码】若保存并运行，保存resolve后再调用start/exec；第二步失败不能承诺已回滚第一步。
5. 【页面观察，来源：前端源码】展示逐项结果并回读策略、任务及运行实例；不能把返回结果弹窗当所有流程成功。

【拟定需求】服务端校验拒绝、重复对象、失权、网络异常与响应结构不合法分别提示。超时结果未知时先回读；不得盲目重放写请求。安全保留草稿、恢复与重复保护的实际行为待运行验证。

| PUT | /schedule/common/flowdefinition/strategys | 策略草稿+整数ids |
| PUT | /schedule/common/flowdefinition/starts | id数组 |
| PUT | /schedule/common/flowdefinition/stops | id数组 |
| PUT | /schedule/common/flowdefinition/execs | id数组 |

【待确认】实际请求序列化、完整DTO、成功响应及业务码、失败响应结构、幂等协议、服务端校验与权限。Promise resolve只证明客户端成功分支写法，不能证明业务操作已成功。
