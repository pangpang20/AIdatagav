## 3. 编号功能需求

### WO-500 工单管理 → 我的待办

**业务目的**：使用者在“工单管理 → 我的待办”处理对应对象；与其他菜单分别保留查询条件、对象标识和处理状态。

【页面观察】实际路径为`/workorder/workbench/workflowReviewList`。

**用户操作与系统响应**：

1. 从“工单管理 → 我的待办”进入目标页，先核对当前部门、空间及对象范围。
2. 页面提供的输入或选择提示为：请选择业务名称、请输入申请标题、请输入发起人、请选择。其匹配方式、默认值和多条件组合语义待确认。
3. 列表展示：序号、数字空间标识、来源应用、工单类型、流水号、业务编号、业务名称、节点名称、申请标题、发起人、发起时间、节点期限、流程状态、操作。记录条数、名称和当时状态属于样本。
4. 可见操作包括：办理。只有本文件另列并附目标页证据的操作才算已进入；其余仅确认入口可见。

【拟定需求】业务依赖：同一申请可产生多个节点工单；办理、撤回、催办和查看分别授权，不能按按钮名称推定执行结果。

**来源与验证**：[H-WO-001](../evidence/live-recheck-20261022/H-WO-001.png) / [页面元素](../evidence/live-recheck-20261022/H-WO-001.json)。仅验证已记载的页面打开和元素读取；接口、持久化、权限隔离和最终业务结果未验证。

#### 3. 业务流程与异常分支（WO-500）

1. 进入工单管理 → 我的待办，读取当前用户、租户/空间和对象标识；页面加载失败时停留在当前页并提供重试。
2. 按字段表填写或选择；缺少必填值、长度越界、格式不合法或确认值不一致时阻止提交并定位字段。
1. 进入工单管理 → 我的待办，在当前用户、租户/空间及数据权限范围内加载页面；加载失败时保留页面上下文并可重试。
2. 按已观察字段设置筛选条件；未确认的匹配方式、默认排序和状态枚举不得由实现人员推断。
3. 查询成功展示结果及分页；空结果与加载失败、无权限、服务异常分别呈现。
4. 网络超时、服务端校验失败、权限不足和响应异常须明确提示并保留筛选条件；不得把空结果判为故障。
5. 分页、重复查询和条件变更不得串用旧响应；较早请求的迟到结果不能覆盖较新的筛选状态。

|---|---|
| 空结果/无权限 | 【拟定需求】明确区分无匹配数据与无权访问，不显示为系统错误。 |
| 网络或服务异常 | 【拟定需求】展示失败状态并保留筛选、分页上下文供重试。 |
| 网络超时/服务端错误 | 【拟定需求】展示可理解的失败状态，保留可安全保留的草稿；结果未知时先查询状态，避免错误重试。 |
| 取消/重复提交 | 【拟定需求】取消不产生未确认写入；重复点击在客户端去重并由服务端幂等保护。 |

- 【待确认】不同分辨率、浏览器缩放、长文本、无数据、权限隐藏、接口慢响应和弹窗溢出时的布局规则。

## 5. 主要流程

### 工单基本信息、业务表单和审核轨迹分区读取

【页面观察】本人相关工单的查看目标是独立详情页，包含基本信息、表单信息、审核历史三个标签。基本信息列业务编号、业务名称、申请标题、申请时间、已流转、流程状态、来源应用和工单类型。三个标签已分别点击取证，具体内容仅以各截图为准。

【拟定需求】办理人应先识别源业务与当前节点，再查看业务表单及已有审核意见；拟定按同一实例和业务版本加载各标签，避免切换工单后沿用上一个工单的缓存。审核历史与当前待办权限分别校验。

【待确认】本人查看详情不等于取得待办办理页；审批、驳回、撤回、委派及重复办理的服务端行为仍未执行。空表单或空历史不能推定源业务无数据。

业务主线：区分待办、已办和本人发起的工单，核对业务申请及审批轨迹。

同一申请可产生多个节点工单；办理、撤回、催办和查看分别授权，不能按按钮名称推定执行结果。

【拟定需求】查询→识别对象→打开目标→核对关联与当前版本→编辑草稿→人工确认→提交→回读结果。正式写入、审批或运行必须有独立授权和服务端结果；本次只执行其中的页面读取部分。
