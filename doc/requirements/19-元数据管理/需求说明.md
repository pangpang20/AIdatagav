# 元数据管理业务需求说明

本轮逐链接进入的目标、表单与字段补充见[子页面与操作细化](./子页面与操作细化.md)；未取得目标的操作仍列待确认。

## 1. 业务目标与使用角色

按数据源组织元数据自动采集任务，并分别管理采集结果与调度状态。

- 使用角色：元数据管理人员、采集运维人员（具体授权范围待确认）。
- 业务入口：数据资产 → 元数据管理。
- 文档状态：基于现有界面的需求草案，供产品、研发和测试评审；角色权限、后端规则和待确认项尚未定稿。

## 2. 业务范围

本模块涉及下列对象。已有界面可以支持定义的功能在第3节展开；尚缺业务规则的操作在第7节逐项登记。

| 业务对象 | 本版可展开的功能 | 尚需定义 |
|---|---|---|
| 自动采集 | 查询与列表、新增、编辑、删除确认 | 详情 |
| 调度策略管理 | 目标业务页面待补充 | 查询与列表、详情、新增、编辑、删除确认 |
| 手动采集 | 目标业务页面待补充 | 查询与列表、详情、新增、编辑、删除确认 |
| 变更管理 | 目标业务页面待补充 | 查询与列表、详情、新增、编辑、删除确认 |
| 版本管理 | 目标业务页面待补充 | 查询与列表、详情、新增、编辑、删除确认 |

## 3. 功能需求

本节用“用户操作—系统响应—业务规则”描述需求。已有界面支持的字段和入口按现有范围整理；带【拟定需求】的行为需产品确认。所有业务验收用例在本轮均未执行。

### MDM-100 查询自动采集

**业务目的**：帮助用户查找自动采集，并核对与后续处理有关的信息。

**操作与规则**：

1. 用户进入自动采集页面。
2. 系统展示当前自动采集信息；具体筛选项见字段规则，未明确命名的条件列入待确认。
3. 结果展示序号、任务名称、调度策略、数据来源名称、任务状态、最后执行时间、采集日志、调度状态，供用户识别对象和核对信息。

**结果与异常处理【拟定需求】**：查询无匹配记录时展示空结果；查询失败时保留条件并允许重试。重置后的默认条件、分页与排序由产品确认。

字段规则见第4节；需求依据见第8节的 MDM-100。

**开发处理细则【拟定需求】**：

- 输入：本操作未取得可编辑输入字段。每个条件的匹配方式与默认值按下述对象规则和公共交互约定执行。
- 响应：查询开始保留条件并显示加载；成功原子替换结果与总数；空结果显示“暂无数据”；失败保留条件、显示错误和重试入口。
- 竞态与恢复：短时间连续查询只展示最后一次条件对应的响应；改变条件从第一页查询；从详情返回恢复已提交条件及页码。
- 数据影响：只读取当前授权范围的数据，不因查看列表改变对象状态；查询条件不等于导出授权。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### MDM-102 新增自动采集

**业务目的**：为指定数据源建立元数据采集计划，明确采集周期与关联策略。

**操作与规则**：

1. 用户从自动采集列表进入新增。
2. 填写任务名称，选择数据源，设置执行周期、关联策略和任务说明。
3. 执行周期提供分、时、日、月、年；关联策略与周期的组合规则待确认。
4. 页面要求“每个数据源只能选择一次”；该限制作用于空间、租户还是全平台待确认。
5. 建立任务定义与启动调度分开处理。

**结果与异常处理【拟定需求】**：提交前校验必填及字段格式；成功后提示结果并在列表显示新记录；失败时保留已填内容；取消返回列表并放弃未提交内容；防止重复提交。

字段规则见第4节；需求依据见第8节的 MDM-102。

**开发处理细则【拟定需求】**：

- 操作前提：用户有自动采集维护权限；关联对象仍存在且属于当前授权范围。修改时须读取目标对象的最新信息。
- 输入集合：任务名称、数据源名称、执行周期、关联策略、任务说明。当前页面保护字段：当前未记录禁用字段。关联选择传递对象标识，显示名称仅供识别。
- 提交校验：必填范围未有完整依据，不能以无星号采样认定全部可选；逐字段应用第4节长度、枚举及联动。前端校验通过后服务端再次校验，不信任禁用控件或客户端上下文。
- 原子结果：主记录和本表单的子项全部成功后才显示成功；任一子项失败不得显示整体已保存。上传文件先后关系按文件条款处理。
- 取消与失败：未提交取消丢弃本次输入并返回来路；提交失败保留输入和子表；超时显示“结果待核实”，先查询结果再重试。
- 重复与冲突：提交期间禁用重复按钮；服务端按同一操作标识去重。修改同时传递版本，版本冲突保留本地输入，提示重新加载后合并。
- 输出：返回稳定对象标识、最新版本和保存结果；列表可按标识定位，刷新或重新进入可读到同一结果。不得用成功提示代替持久化结果。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### MDM-103 修改自动采集

**业务目的**：维护已有自动采集的信息；本模块的用途是按数据源组织元数据自动采集任务，并分别管理采集结果与调度状态。

**操作与规则**：

1. 用户选择已有自动采集并进入修改页面。
2. 系统回显原有信息；用户修改允许维护的字段，字段范围见第4节。
3. 本表单可维护的信息包括执行周期、关联策略、任务说明；各项必填和长度规则见字段表。
4. 当前编辑场景中任务名称、数据源名称不可修改；其他状态下是否允许变更见待确认项。
5. 任务执行周期、关联策略和说明与任务标识分别管理；任务状态和调度状态分别显示。

**结果与异常处理【拟定需求】**：保存前校验允许修改的字段；成功后刷新对象信息；失败保留输入；取消放弃未保存修改；并发修改时给出明确处理结果。

字段规则见第4节；需求依据见第8节的 MDM-103。

**开发处理细则【拟定需求】**：

- 输入集合：执行周期、关联策略、任务说明。当前页面保护字段：任务名称、数据源名称。关联选择传递对象标识，显示名称仅供识别。

- 原子结果：主记录和本表单的子项全部成功后才显示成功；任一子项失败不得显示整体已保存。上传文件先后关系按文件条款处理。
- 取消与失败：未提交取消丢弃本次输入并返回来路；提交失败保留输入和子表；超时显示“结果待核实”，先查询结果再重试。

### MDM-104 删除自动采集

**业务目的**：移除不再需要的自动采集定义，并明确对关联业务的影响。

**操作与规则**：

1. 用户对目标自动采集发起删除。
2. 系统展示删除确认，要求用户确认后再执行。
3. 【页面文案】删除确认提示为：警告 / 删除操作不能恢复，确定删除吗？ / 取 消 确 认。
4. 取消与确认分别处理；确认删除后的实际影响按产品确认的删除规则执行。

**结果与异常处理【拟定需求】**：确认中明确对象及影响范围；取消保留对象；存在引用或运行中任务时按确认后的策略阻止或提示；失败可重试，同一删除请求不重复生效。

字段规则见第4节；需求依据见第8节的 MDM-104。

**开发处理细则【拟定需求】**：

- 输入与确认：使用所选自动采集的标识和当前版本，确认层展示名称及影响范围；不得凭显示序号或模糊名称定位。
- 确认前检查：重新校验删除权限、版本、引用关系及运行状态；具体禁止条件列于第7节，未确认时不实现自动级联删除。
- 确认/取消：取消关闭确认层且不发送业务删除；确认后显示处理中，成功才移出当前结果；删掉当前页最后一条时重查有效页。
- 异常与恢复：引用阻止则展示可定位的关联业务；无权/版本冲突/处理中失败分别提示；超时先核对对象是否仍存在，重复确认不重复清理关联项。
- 删除边界：平台记录、子配置、外部资源及历史记录逐项确定；在删除策略未评审前只可制作确认界面。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### MDM-001 区分采集任务与调度状态

**业务目的**：按数据源组织元数据自动采集任务，并分别管理采集结果与调度状态。

**操作与规则**：

1. 元数据采集区分自动和手动；自动采集列表展示任务名称、调度策略、数据源、任务状态、最后执行、日志及调度状态。
2. 任务状态与调度状态分列展示，应分别用于判断采集任务和调度情况。

**业务规则与待确认**：两类状态的完整枚举、迁移条件、日志和执行关系待确认。

**结果与异常处理【拟定需求】**：无法访问或加载失败时给出明确提示，保留可恢复的业务上下文。

**开发处理细则【拟定需求】**：

- 输入与范围：采用当前用户、租户、空间和页面明确的时间/分类条件；未定义统计口径的指标只可展示样稿，不实现猜测算法。
- 响应状态：首次加载、刷新、空数据、部分指标失败和失权分别展示；失败指标不填0冒充成功，显示数据时间及重试入口。
- 入口：菜单目标独立验权；只有取得目标页面证据的范围才在本模块定义业务功能。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

## 5. 主要业务流程

【拟定需求】业务流程草案：选择数据源 → 设置执行周期和策略 → 建立采集任务 → 跟踪采集与调度；启动和执行规则待确认。各环节之间的自动流转、数据传递和状态联动需产品确认，不能由导航入口推定。

【拟定需求】用户在保存、删除、发布、审批、授权或任务运行前应明确操作对象和影响；成功给出结果，失败保留可恢复信息，取消策略及重复操作规则统一评审。

### AI开发审查结论

- 可先实现：本模块已列出的入口、展示结构、明确字段长度、当前禁用状态，以及公共规则中的加载/空/失败/取消界面；使用模拟数据实现时明确标示。
- 业务写入与执行：尚未达到生产开发就绪。来源唯一域、周期与策略组合、状态迁移、日志/版本/变更及取消返回异常是必须明确的业务输入，不允许AI自行选择一套并当成已确认规则。
- 拟定需求的使用：可据此制作交互原型和评审稿；正式持久化、权限、接口和外部任务行为需评审规则及接口协议后再实现。
- 本模块全部查询/详情/新增/修改/删除的逐对象范围保留于本节登记；未知操作不视为产品确定支持。

| 检查项 | 本版结论 |
|---|---|
| 字段与输入边界 | 已观察维护操作3项；明确部分字段及子配置。 |
| 状态与权限 | 当前样本不是完整状态机；角色/空间/部门权限待业务定义。 |
| 成功及异常 | 本文处理细则与公共规则已提出可测试建议，尚未验证应用写入。 |
| 数据模型与接口 | 本文给逻辑对象和输入输出语义，未规定物理表或虚构现网API。开发协议须单独评审。 |
| 验收 | 每条用例均拟定未执行；字段边界、取消/重试、权限、重复及恢复已按适用操作展开。 |
