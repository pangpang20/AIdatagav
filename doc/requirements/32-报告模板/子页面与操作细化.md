#### 2. 页面交互规则（RTMS-500）

| 控件/触发 | 行为与反馈 |

#### 3. 业务流程与异常分支（RTMS-500）

进入列表 → 服务端按会话范围读取候选及结果 → 设置名称/类型/状态 → 提交查询 → 成功时同时替换列表、总数和分页。无匹配、无权与失败分开；超时保留条件并允许只读重试。

#### 4. 接口与数据规则（RTMS-500）

列表与候选读取的方法与相对路径、筛选/分页/排序字段、枚举、响应数据与总数字段由RTMS查询合同交付。页面路由不是API地址；没有真实合同不得编造成功码、默认页大小或请求结构。

HTTP成功与业务成功分别判断；会话过期停止写入，不自动重放保存/删除。身份、对象及关联范围使用服务端合同，普通日志不记录秘密。

### 接口、数据与权限边界

RTMS-500的列表/候选读取，RTMS-501的文件上传、步骤校验及最终创建，RTMS-502的回显/更新，以及删除的确认提交与结果回查，分别使用经过评审的API合同。HTTP方法、相对路径、Content-Type、请求字段与类型、空值转换、枚举、响应成功判断和错误结构均由该合同提供。页面路由不是API地址；没有合同不得生成猜测的URL或成功响应。

服务端对会话、动作、对象和关联资源分别鉴权；菜单、按钮、前端禁用和客户端范围参数均不能扩大授权。会话过期停止后续写入并提示重新鉴权，不自动恢复保存或删除。对象标识、版本、幂等标识和临时文件归属由服务端合同提供；显示名称不能替代稳定标识。所有读取/上传/下载/写入使用平台批准的TLS配置，不保存令牌、Cookie或文件正文到普通日志或浏览器持久存储。

### 页面状态与质量要求

列表具有初始化、加载、可操作、空结果、错误和无权状态；表单具有加载、编辑、字段错误、步骤处理中、明确失败和结果未知状态。错误保留安全上下文并提供针对性恢复；成功以最终回读为准。删除确认层的焦点进入模态、关闭后返回原触发控件，键盘不得穿透背景。

RTMS-500关联RTMS-NFR-001、003、004、005、006；RTMS-501/502关联RTMS-NFR-002、003、004、005、006、007、008。完整指标、测量环境与失败条件见[主文质量要求](./需求说明.md#非功能需求)，全部质量验收未执行。

## 5. 主要流程

1. 查询：进入列表并加载授权范围内数据；设置筛选并查询；分页、重置及失败重试遵循批准的接口契约。
2. 新增：填写基本资料，按文件安全策略选择模板，再进入待补充的设计/绑定步骤；最终保存并回读对象。
3. 编辑：读取当前对象与版本，只修改经对象状态允许的字段；保存成功后回读，冲突时不覆盖新版本。
4. 删除：打开确认层；取消保持对象不变；确认前由服务端检查权限、引用及状态并返回明确结果。
