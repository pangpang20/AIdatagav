- 业务入口：数据评价 → 报告模板。
- 文档状态：基于现有界面的需求草案，供产品、研发和测试评审；角色权限、后端规则和待确认项尚未定稿。

### RTMS-100 查询报告模板

**业务目的**：帮助用户查找报告模板，并核对与后续处理有关的信息。

**操作与规则**：

1. 用户进入报告模板页面。
2. 用户可按模板名称、报告类型、状态设置条件，查询所需记录。
3. 结果展示序号、模板名称、部门名称、适用对象、模板说明、报告类型、状态、被引用数、创建时间，供用户识别对象和核对信息。

**结果与异常处理【拟定需求】**：查询无匹配记录时展示空结果；查询失败时保留条件并允许重试。重置后的默认条件、分页与排序由产品确认。

字段规则见第4节；需求依据见第8节的 RTMS-100。

**开发处理细则【拟定需求】**：

- 输入：模板名称、报告类型、状态。每个条件的匹配方式与默认值按下述对象规则和公共交互约定执行。
- 响应：查询开始保留条件并显示加载；成功原子替换结果与总数；空结果显示“暂无数据”；失败保留条件、显示错误和重试入口。
- 竞态与恢复：短时间连续查询只展示最后一次条件对应的响应；改变条件从第一页查询；从详情返回恢复已提交条件及页码。
- 数据影响：只读取当前授权范围的数据，不因查看列表改变对象状态；查询条件不等于导出授权。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### RTMS-102 新增报告模板

**业务目的**：维护可供报告引用的模板说明及文件。

**操作与规则**：

1. 用户从报告模板列表进入新增。
2. 填写模板名称、适用对象、报告类型和模板说明。
3. 上传文案要求docx文件且不超过10MB；页面提示粘贴图片可能造成异常，应在正式模板规范中明确处理方式。
4. 点击下一步进入后续模板配置；后续设计器、指标绑定和各步保存规则待确认。

**结果与异常处理【拟定需求】**：下一步校验当前步骤，并在回退时保留已填内容；最终提交后给出结果。草稿保存时机、成功去向和取消策略由产品确认。

字段规则见第4节；需求依据见第8节的 RTMS-102。

**开发处理细则【拟定需求】**：

- 操作前提：用户有报告模板维护权限；关联对象仍存在且属于当前授权范围。修改时须读取目标对象的最新信息。
- 输入集合：模板名称、适用对象、报告类型、模板说明、模板文件。当前页面保护字段：当前未记录禁用字段。关联选择传递对象标识，显示名称仅供识别。
- 提交校验：模板名称、报告类型；逐字段应用第4节长度、枚举及联动。前端校验通过后服务端再次校验，不信任禁用控件或客户端上下文。
- 原子结果：主记录和本表单的子项全部成功后才显示成功；任一子项失败不得显示整体已保存。上传文件先后关系按文件条款处理。
- 取消与失败：未提交取消丢弃本次输入并返回来路；提交失败保留输入和子表；超时显示“结果待核实”，先查询结果再重试。
- 重复与冲突：提交期间禁用重复按钮；服务端按同一操作标识去重。修改同时传递版本，版本冲突保留本地输入，提示重新加载后合并。
- 输出：返回稳定对象标识、最新版本和保存结果；列表可按标识定位，刷新或重新进入可读到同一结果。不得用成功提示代替持久化结果。
- 多步例外：下一步仅推进当前编辑流程；最终步骤保存前不得宣称主对象已创建。步骤暂存、草稿和取消清理为开发前阻断项。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### RTMS-103 修改报告模板

**业务目的**：维护已有报告模板的信息；本模块的用途是维护可复用报告模板，供相关检测或评价报告引用。

**操作与规则**：

1. 用户选择已有报告模板并进入修改页面。
2. 系统回显原有信息；用户修改允许维护的字段，字段范围见第4节。
3. 本表单可维护的信息包括适用对象、模板说明；各项必填和长度规则见字段表。
4. 当前编辑场景中模板名称、报告类型、质量检测方案、模板文件不可修改；其他状态下是否允许变更见待确认项。

**结果与异常处理【拟定需求】**：保存前校验允许修改的字段；成功后刷新对象信息；失败保留输入；取消放弃未保存修改；并发修改时给出明确处理结果。

字段规则见第4节；需求依据见第8节的 RTMS-103。

**开发处理细则【拟定需求】**：

- 原子结果：主记录和本表单的子项全部成功后才显示成功；任一子项失败不得显示整体已保存。上传文件先后关系按文件条款处理。
- 取消与失败：未提交取消丢弃本次输入并返回来路；提交失败保留输入和子表；超时显示“结果待核实”，先查询结果再重试。
- 重复与冲突：提交期间禁用重复按钮；服务端按同一操作标识去重。修改同时传递版本，版本冲突保留本地输入，提示重新加载后合并。
- 输出：返回稳定对象标识、最新版本和保存结果；列表可按标识定位，刷新或重新进入可读到同一结果。不得用成功提示代替持久化结果。

### RTMS-104 删除报告模板

**业务目的**：移除不再需要的报告模板定义，并明确对关联业务的影响。

**操作与规则**：

1. 用户对目标报告模板发起删除。
2. 系统展示删除确认，要求用户确认后再执行。
3. 【页面文案】删除确认提示为：警告 / 删除操作不能恢复，确定删除吗？ / 取 消 确 认。
4. 取消与确认分别处理；确认删除后的实际影响按产品确认的删除规则执行。

**结果与异常处理【拟定需求】**：确认中明确对象及影响范围；取消保留对象；存在引用或运行中任务时按确认后的策略阻止或提示；失败可重试，同一删除请求不重复生效。

字段规则见第4节；需求依据见第8节的 RTMS-104。

**开发处理细则【拟定需求】**：

- 输入与确认：使用所选报告模板的标识和当前版本，确认层展示名称及影响范围；不得凭显示序号或模糊名称定位。
- 确认前检查：重新校验删除权限、版本、引用关系及运行状态；具体禁止条件列于第7节，未确认时不实现自动级联删除。
- 确认/取消：取消关闭确认层且不发送业务删除；确认后显示处理中，成功才移出当前结果；删掉当前页最后一条时重查有效页。
- 异常与恢复：引用阻止则展示可定位的关联业务；无权/版本冲突/处理中失败分别提示；超时先核对对象是否仍存在，重复确认不重复清理关联项。
- 删除边界：平台记录、子配置、外部资源及历史记录逐项确定；在删除策略未评审前只可制作确认界面。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### RTMS-001 查找报告模板及使用状态

**业务目的**：维护可复用报告模板，供相关检测或评价报告引用。

**操作与规则**：

1. 模板列表展示名称、部门、对象、说明、报告类型、状态、被引用数和创建信息；提供复制、发布和取消发布入口。

**业务规则与待确认**：发布与引用版本、设计器、动态绑定及引用保护待确认。

**结果与异常处理【拟定需求】**：无法访问或加载失败时给出明确提示，保留可恢复的业务上下文。

**开发处理细则【拟定需求】**：

- 输入与范围：采用当前用户、租户、空间和页面明确的时间/分类条件；未定义统计口径的指标只可展示样稿，不实现猜测算法。
- 响应状态：首次加载、刷新、空数据、部分指标失败和失权分别展示；失败指标不填0冒充成功，显示数据时间及重试入口。
- 入口：菜单目标独立验权；只有取得目标页面证据的范围才在本模块定义业务功能。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

## 5. 主要业务流程

【拟定需求】业务流程草案：填写模板信息 → 上传模板文件 → 配置报告内容 → 供报告引用；设计器和绑定规则待确认。各环节之间的自动流转、数据传递和状态联动需产品确认，不能由导航入口推定。

【拟定需求】用户在保存、删除、发布、审批、授权或任务运行前应明确操作对象和影响；成功给出结果，失败保留可恢复信息，取消策略及重复操作规则统一评审。

### AI开发审查结论

- 可先实现：本模块已列出的入口、展示结构、明确字段长度、当前禁用状态，以及公共规则中的加载/空/失败/取消界面；使用模拟数据实现时明确标示。
- 业务写入与执行：尚未达到生产开发就绪。设计器/绑定、适用对象与类型联动、文件边界、发布/引用保护和导出是必须明确的业务输入，不允许AI自行选择一套并当成已确认规则。
- 拟定需求的使用：可据此制作交互原型和评审稿；正式持久化、权限、接口和外部任务行为需评审规则及接口协议后再实现。
