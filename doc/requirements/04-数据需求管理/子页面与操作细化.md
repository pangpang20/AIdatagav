**业务目的**：使用者在“调研概览”处理对应对象；与其他菜单分别保留查询条件、对象标识和处理状态。

【页面观察】实际路径为`/dop/dbms/requirement/overview/chart`。

**用户操作与系统响应**：

1. 从“调研概览”进入目标页，先核对当前部门、空间及对象范围。
2. 当前样本没有可用于完整定义检索条件的输入，不能推测支持全文或模糊查询。
3. 该页不按普通表格定义；实际卡片、图形或前置提示以来源截图为准。
4. 未取得可独立识别的行内操作；不推定存在维护能力。

【拟定需求】业务依赖：调研单位—团队—计划—里程碑—成果清单的关联键、成果提交条件和归集规则需确认；不同清单不能互相代替。

**来源与验证**：[H-DBMS-001](../evidence/live-recheck-20261022/H-DBMS-001.png) / [页面元素](../evidence/live-recheck-20261022/H-DBMS-001.json)。仅验证已记载的页面打开和元素读取；接口、持久化、权限隔离和最终业务结果未验证。

### DBMS-501 调研准备 → 委办局信息

**业务目的**：使用者在“调研准备 → 委办局信息”处理对应对象；与其他菜单分别保留查询条件、对象标识和处理状态。

【页面观察】实际路径为`/dop/dbms/requirement/prepare/office`。当前可见字段：调研目的：。

**用户操作与系统响应**：

1. 从“调研准备 → 委办局信息”进入目标页，先核对当前部门、空间及对象范围。
2. 页面提供的输入或选择提示为：调研目的：、请输入委办局名称、请输入委办局领导。其匹配方式、默认值和多条件组合语义待确认。
3. 列表展示：序号、调研委办局、委办局领导、委办局地址、联系人、联系人电话、科室、描述、操作。记录条数、名称和当时状态属于样本。
4. 可见操作包括：新增、导入、导出。只有本文件另列并附目标页证据的操作才算已进入；其余仅确认入口可见。

【页面观察】采样中出现“暂无数据”；它可能属于列表、下拉或子表，须结合截图定位。不能据此宣称整个模块无数据，也不能用空列表证明查询失败。

【拟定需求】业务依赖：调研单位—团队—计划—里程碑—成果清单的关联键、成果提交条件和归集规则需确认；不同清单不能互相代替。

**来源与验证**：[H-DBMS-002](../evidence/live-recheck-20261022/H-DBMS-002.png) / [页面元素](../evidence/live-recheck-20261022/H-DBMS-002.json)。仅验证已记载的页面打开和元素读取；接口、持久化、权限隔离和最终业务结果未验证。

**业务目的**：使用者在“调研准备 → 委办局信息”处理对应对象；与其他菜单分别保留查询条件、对象标识和处理状态。

**操作流程**：

## 5. 主要流程

### 调研计划需要关联准备资料

【页面观察】委办局维护组织与联系人资料；团队维护名称、组长和成员。新增计划选择里程碑阶段、调研委办局、调研方式和调研团队，另填地点、联系人、电话、时间、科室和描述。科室、地点、联系人、电话的maxlength均为100，描述200；这不证明电话格式或时间边界。

【拟定需求】计划人员应能核对调研对象和团队后安排时间；拟定按组织、团队及里程碑稳定标识关联。人员离职、团队变动和关联对象停用时保留计划历史快照，变更未来计划需重新确认负责范围。

【待确认】委办局是否自动回填联系人、时间冲突检查、团队多选规则、里程碑顺序及实施成果归集条件待确认。
