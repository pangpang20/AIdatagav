# 数据需求管理业务需求说明

本轮逐链接进入的目标、表单与字段补充见[子页面与操作细化](./子页面与操作细化.md)；未取得目标的操作仍列待确认。

## 1. 业务目标与使用角色

组织委办局数据调研，维护调研团队、里程碑、实施资料及归集成果。

- 使用角色：调研负责人、调研成员（角色名称待确认）。
- 业务入口：需求管理 → 数据需求管理。
- 文档状态：基于现有界面的需求草案，供产品、研发和测试评审；角色权限、后端规则和待确认项尚未定稿。

## 2. 业务范围

本模块涉及下列对象。已有界面可以支持定义的功能在第3节展开；尚缺业务规则的操作在第7节逐项登记。

| 业务对象 | 本版可展开的功能 | 尚需定义 |
|---|---|---|
| 调研委办局 | 查询与列表、新增 | 详情、编辑、删除确认 |
| 调研里程碑 | 查询与列表、新增 | 详情、编辑、删除确认 |
| 配置管理 | 查询与列表、详情 | 新增、编辑、删除确认 |
| 调研团队 | 查询与列表、新增 | 详情、编辑、删除确认 |
| 调研计划列表 | 查询与列表 | 详情、新增、编辑、删除确认 |
| 调研实施 | 查询与列表 | 详情、新增、编辑、删除确认 |
| 数据归集 | 查询与列表 | 详情、新增、编辑、删除确认 |
| 参考文档 | 目标业务页面待补充 | 查询与列表、详情、新增、编辑、删除确认 |
| 调研报告 | 目标业务页面待补充 | 查询与列表、详情、新增、编辑、删除确认 |

## 3. 功能需求

本节用“用户操作—系统响应—业务规则”描述需求。已有界面支持的字段和入口按现有范围整理；带【拟定需求】的行为需产品确认。所有业务验收用例在本轮均未执行。

### DBMS-100 查询调研委办局

**业务目的**：帮助用户查找调研委办局，并核对与后续处理有关的信息。

**操作与规则**：

1. 用户进入调研委办局页面。
2. 用户可按委办局名称、委办局领导设置条件，查询所需记录。
3. 结果展示序号、调研委办局、委办局领导、委办局地址、联系人、联系人电话、科室、描述，供用户识别对象和核对信息。

**结果与异常处理【拟定需求】**：查询无匹配记录时展示空结果；查询失败时保留条件并允许重试。重置后的默认条件、分页与排序由产品确认。

字段规则见第4节；需求依据见第8节的 DBMS-100。

**开发处理细则【拟定需求】**：

- 输入：委办局名称、委办局领导。每个条件的匹配方式与默认值按下述对象规则和公共交互约定执行。
- 响应：查询开始保留条件并显示加载；成功原子替换结果与总数；空结果显示“暂无数据”；失败保留条件、显示错误和重试入口。
- 竞态与恢复：短时间连续查询只展示最后一次条件对应的响应；改变条件从第一页查询；从详情返回恢复已提交条件及页码。
- 数据影响：只读取当前授权范围的数据，不因查看列表改变对象状态；查询条件不等于导出授权。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### DBMS-102 新增调研委办局

**业务目的**：组织委办局数据调研，维护调研团队、里程碑、实施资料及归集成果。

**操作与规则**：

1. 用户从调研委办局列表进入新增。
2. 登记委办局、领导、联系人及其职务和电话；补充科室、地址和描述。
3. 联系信息用于后续调研联络；电话号码格式规则待业务确认。

**结果与异常处理【拟定需求】**：提交前校验必填及字段格式；成功后提示结果并在列表显示新记录；失败时保留已填内容；取消返回列表并放弃未提交内容；防止重复提交。

字段规则见第4节；需求依据见第8节的 DBMS-102。

**开发处理细则【拟定需求】**：

- 操作前提：用户有调研委办局维护权限；关联对象仍存在且属于当前授权范围。修改时须读取目标对象的最新信息。
- 输入集合：调研委办局、委办局领导、联系人、联系人职务、联系人电话、科室、委办局地址、描述。当前页面保护字段：当前未记录禁用字段。关联选择传递对象标识，显示名称仅供识别。
- 提交校验：调研委办局、委办局领导、联系人、联系人职务、联系人电话；逐字段应用第4节长度、枚举及联动。前端校验通过后服务端再次校验，不信任禁用控件或客户端上下文。
- 原子结果：主记录和本表单的子项全部成功后才显示成功；任一子项失败不得显示整体已保存。上传文件先后关系按文件条款处理。
- 取消与失败：未提交取消丢弃本次输入并返回来路；提交失败保留输入和子表；超时显示“结果待核实”，先查询结果再重试。
- 重复与冲突：提交期间禁用重复按钮；服务端按同一操作标识去重。修改同时传递版本，版本冲突保留本地输入，提示重新加载后合并。
- 输出：返回稳定对象标识、最新版本和保存结果；列表可按标识定位，刷新或重新进入可读到同一结果。不得用成功提示代替持久化结果。

这些细则是待产品评审的实现建议；页面事实及本对象特有依赖以第4、7、8节为准。

### AI开发审查结论

- 可先实现：本模块已列出的入口、展示结构、明确字段长度、当前禁用状态，以及公共规则中的加载/空/失败/取消界面；使用模拟数据实现时明确标示。
- 业务写入与执行：尚未达到生产开发就绪。计划/实施/成果的字段、阶段完成口径、人员选择范围、日期先后及重叠规则是必须明确的业务输入，不允许AI自行选择一套并当成已确认规则。
- 拟定需求的使用：可据此制作交互原型和评审稿；正式持久化、权限、接口和外部任务行为需评审规则及接口协议后再实现。
- 本模块全部查询/详情/新增/修改/删除的逐对象范围保留于本节登记；未知操作不视为产品确定支持。
