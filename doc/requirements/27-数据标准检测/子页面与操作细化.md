## 3. 编号功能需求

### DSTS-500 标准检测 → 检测方案

**业务目的**：使用者在“标准检测 → 检测方案”处理对应对象；与其他菜单分别保留查询条件、对象标识和处理状态。

【页面观察】实际路径为`/dsts/standard/plan/list`。当前页面标题：检测方案。

**用户操作与系统响应**：

1. 从“标准检测 → 检测方案”进入目标页，先核对当前部门、空间及对象范围。
2. 页面提供的输入或选择提示为：请输入方案名称、请选择状态。其匹配方式、默认值和多条件组合语义待确认。
3. 列表展示：序号、方案名称、适用对象、方案说明、状态、适用标准字段、任务、创建时间、操作。记录条数、名称和当时状态属于样本。
4. 可见操作包括：复制、启用、取消启用。只有本文件另列并附目标页证据的操作才算已进入；其余仅确认入口可见。

【页面观察】采样中出现“暂无数据”；它可能属于列表、下拉或子表，须结合截图定位。不能据此宣称整个模块无数据，也不能用空列表证明查询失败。

【拟定需求】业务依赖：对象唯一范围、引用关系、生命周期状态、读写权限及生效条件需逐项确认；不能从当前记录样本推定全量规则。

**来源与验证**：[F-DSTS-001](../evidence/live-recheck-20261022/F-DSTS-001.png) / [页面元素](../evidence/live-recheck-20261022/F-DSTS-001.json)。仅验证已记载的页面打开和元素读取；接口、持久化、权限隔离和最终业务结果未验证。

## 5. 主要流程

### 标准检测新增只是分步流程的第一步

【页面观察】标准检测新增第一页含任务名称、检测方案、报告模板、任务说明，底部为取消和下一步；方案与模板下拉已展开采样。没有进入后续步骤或执行检测。

【拟定需求】拟定先确定检测方案及其版本、报告模板，再选择授权数据范围并复核后提交。步骤间返回保留草稿；方案/模板失效、权限变化和并发更新应在确认前重新检查。任务保存与启动分别处理。

【待确认】后续步骤、检测标准匹配、阈值、算法、报告形成、失败重试与版本生效未取得证据。

来源：[F-DSTS-002-op1](../evidence/live-recheck-20261022/F-DSTS-002-op1.png) / [页面元素](../evidence/live-recheck-20261022/F-DSTS-002-op1.json)。

业务主线：配置标准检测方案并读取检测报告。

跨模块关联仅在页面显示引用时建立；接口和状态契约待评审。

【拟定需求】查询→识别对象→打开目标→核对关联与当前版本→编辑草稿→人工确认→提交→回读结果。正式写入、审批或运行必须有独立授权和服务端结果；本次只执行其中的页面读取部分。
