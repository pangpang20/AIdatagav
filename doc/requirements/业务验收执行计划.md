# 业务验收执行计划

本计划把已补证功能转成可执行步骤；状态全部为【拟定，未执行】。当前应用继续受“不插入、不修改、不删除业务数据、不执行任务或权限变更”的约束。本轮只读静态资源和离线文档校验不能替代本计划的应用验收，也不能据此认定账号唯一性、服务端校验或任务运行已经通过。

执行对象须为获授权的隔离测试环境、专用测试账号与可丢弃数据。生产账号和原有任务不得作测试对象。取得环境授权后，先补齐实际接口响应与产品规则，再执行依赖它们的检查；授权前不得为了补证提交写请求。只读打开维护页面仍属于允许范围，但本轮工具无法继续控制既有登录浏览器，未补造点击记录或新截图。

## 1. 执行前数据与记录

| 对象 | 准备方式 | 必须登记的证据 |
|---|---|---|
| 测试用户 | 由测试环境管理员准备合法账号、重复账号、无管理权限账号；账号值不写入共享文档 | userId、身份类别、范围、数据归属和操作前记录；秘密留在批准的凭证渠道 |
| 部门与租户 | 准备两部门、两租户及仅属于一个范围的用户；至少一条有引用的对象 | deptId、tenantId、成员关系id、授权集合和原主部门 |
| 角色与权限 | 准备可管理角色、不可管理的既有角色，以及带directDepend的权限 | roleId、权限树版本、依赖关系、授权前集合 |
| 采集任务 | 断开真实外部写入，使用隔离源/目标；准备库表和CSV两种目标 | taskId、数据源授权、映射草稿、运行/停止前状态和测试运行记录 |
| 流程调度 | 使用专用流程，禁用外部通知及生产依赖；准备单个和多项选择 | flowId、策略原值、status/configStatus、实例清单及时间基准 |
| 故障与权限 | 使用测试代理或服务端测试能力注入超时、校验拒绝、403与500 | 请求关联号、故障生效时机、实际HTTP与业务返回；不记录认证头和秘密值 |

每条用例执行前保存快照，执行后按稳定ID回读。仅看到成功提示不算通过；写入类需同时取得请求、真实响应和回读结果。失败时记录实际行为及与需求的差异，不把拟定结果改写为既有实现。恢复测试数据须另行获授权，不能在只读调研中用“清理”名义删除对象。
